Country Code Helper 测试场

本页面包含 10 种不同结构的区号 <select> 场景，用于精准测试脚本的识别逻辑。安装 Tampermonkey 并启用脚本后，刷新本页查看 🌐 图标是否出现。

⚠️ 为什么 CodePen 和 intl-tel-input 未生效？

CodePen（ExzVrPY）：该 Pen 使用的是 <div> + CSS 模拟的自定义下拉框，并非原生 <select> 元素。脚本只扫描 tagName === 'SELECT' 的原生元素，因此无法识别。

intl-tel-input：该库会将原生 <input type="tel"> 包装并生成自定义旗帜下拉 UI，底层同样不是 <select>，所以脚本检测不到。

这两个场景揭示了脚本当前的核心局限：只能处理原生 <select> 元素，无法覆盖基于 div/ul/input 的自定义下拉组件。

🔍 脚本检测通过条件（需同时满足）

①

必须是原生 <select>自定义 div/ul 下拉框不被识别

②

属性含关键词 OR 内容含国家名name/id/class/aria-label 含 country/phone/dial 等，或选项含 China/Japan 等

③

至少 2 个选项值匹配区号格式即值符合 +XX / 00XX / 纯数字 1-4 位

④

满足②+③，或②单独满足时含国家名多重兜底策略，优先属性关键词

✓ 应触发 脚本应识别并显示 🌐 图标
✗ 不触发 刻意设计为不被识别（负面测试）
△ 边缘 处于检测边界，结果取决于当前逻辑
⊕ 动态 元素在页面加载后动态插入
第一组 · 属性关键词触发（最核心）
Case 1 — name 属性含关键词
select 的 name="countrycode"，值为标准 +XX 格式
✓ 应触发
触发路径: name="countrycode" → 含 "country" → hasCodeOptions ✓
Case 2 — id 属性含 "dial"
select 的 id="dialCode"，值为 00XX 格式
✓ 应触发
触发路径: id="dialCode" → 含 "dial" → hasCodeOptions ✓
Case 3 — class 含 "phone-code"
通过 className 检测，值为纯数字格式
✓ 应触发
触发路径: class 含 "phone-code" → hasCodeOptions（纯数字1-4位）✓
Case 4 — aria-label 含关键词
无 name/id，仅通过 aria-label 触发
✓ 应触发
触发路径: aria-label 含 "country" + "calling" → hasCodeOptions ✓
第二组 · 父元素 / label 文字触发（兜底策略）
Case 5 — 父元素文字含 "phone"
select 本身无关键词属性，靠父容器文字触发
✓ 应触发

Case 6 — <label for> 关联文字

✓ 应触发
触发路径: label[for="c6_sel"] 文字含 "country" + "code" → hasCodeOptions ✓
Case 7 — 选项值含国家名
无任何属性关键词，靠选项文本中的国家名触发（最后一道兜底）
△ 边缘

Case 8 — data-name 自定义属性
使用 data-name="area-code" 触发
✓ 应触发
