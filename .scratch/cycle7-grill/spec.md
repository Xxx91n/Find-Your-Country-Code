## Problem Statement

Cycle-6 已把功能面推到「设置可找到 / 失效可解释 / 生效可证明」三事成立（12/12 票闭合、v1.7.0 已发）。Round-4 锐评自评「功能层已追平所有批评」，剩余为**结构性烂账**；同时 backlog（`B-5…B-15`）与化石清单尚未裁定。

锐评的 git 类与 GF 类指控经**实物核验部分为幻觉**（详 D-001 上游核验）：
- 「第四次历史归零」为**假**：`origin/main` tip `a93cb3a8` **有父提交**，共 290 commits，`v1.3.4…v1.7.0` **全部为 main 祖先**。
- 「GF 每日哨兵连看几天红」为**假**：最近 3 次运行全部 success（`--strict` 未开启）。
- GF 版本漂移**为真**：GF `@version` 实测 1.5.0，仓库 1.7.0。

## Solution

本轮**同时**推进两条线（D-001）：
- **A｜收口债清账**：锐评 5 工单 ＋ backlog `B-5…B-15` ＋ 化石清单，逐条裁定「立票／不立票／登记」。
- **B｜检测能力扩张**：在既有语料与 ADR 裁决口上扩张（contenteditable 端到端、伪 select 二次裁决）。
- **排除**：不新开 `improve-codebase-architecture` 宏观调查周期。

## 交付口径

- **本轮不发新版本**（D-018）：A 侧清账与 B 侧扩张照常修复并落地，但**不 bump 版本、不触发 release**；变更**累积**到后续再发版。
- 推论：**ADR-0010 发布门本轮不触发**（无 release 事件）——收口时须**显式登记「未触发原因＝本轮无发版」**，不得静默缺席。
- 推论：**D-002 的送达链闭合验证随之推迟**（无新版本可同步）——D-002 的①自查与②权威声明仍照做，但**不得声称「送达链已闭合」**。
