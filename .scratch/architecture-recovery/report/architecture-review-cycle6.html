00目标（/goal · 不设预算）

上轮（Cycle-5）把「送达 + 可见 + 可信」做完了，但两个痛点指向同一个未完成的事：脚本的功能「存在」不等于「能被找到」，更不等于「能被证明」。本轮目标是把系统从「功能已实现」推进到「功能可被发现、可被解释、可被证明」。

G1 · 可配置

设置能被找到

语言设置今天埋在第 3 层且无任何直达入口。目标：任何设置都从一个稳定的、与字段置信度无关的入口可达。

判据：冷启动 ≤2 次点击到达语言设置；GM 菜单含「设置」项。

G2 · 可解释

生效与否可查询

今天脚本零 console 输出、无自检面，评分证据链算完即丢。目标：任一页面都能回答「各工具是否生效、为何未生效」。

判据：存在诊断面，逐层点亮并给出已验证的根因。

G3 · 可证明

指定页全工具验证

真实站点层 18 项能力只验证 2 项，核心「选国→填充」在真实页面上从未验证过一次。目标：在自有指定页面上完成 L0–L5 全断言。

判据：owned 指定页覆盖全部工具面且全绿；真实站点层保留 L0–L2。

推进方式：以 message 步骤（§06）为单位推进，每步一个可验收闭环；不设时间/成本预算。
硬边界：本大脑代理不直接修改代码——调查→立票→实施分离；实施走 to-spec / to-tickets / implement，版本控制走 but 独立分支。

01执行摘要

上轮把「送达、可见、可信」做完了，本轮四条硬证据指向一个共同的架构形状：状态与行为已经写进代码，但既没有对用户可达的「配置面」，也没有对人与 CI 可读的「解释面」。

实证 1

语言设置埋在第 3 层

控件确实存在（#cch-locale-tg，ui/index.ts:532），但路径是「图标 → 面板 → ⚙ #cch-rules-tg → 滚动到底」。它排在豁免/规则/低调样式之后，而容器是 overflow-y:auto（ui/index.ts:101）——豁免域名越多，语言控件被推得越靠下。无独立入口、无 GM 菜单项。

实证 2

指定页面只验证了 2/18 项能力

tests/live/live-smoke.mjs 全文无任何 .click() / .fill() / locator()；唯一读面是数 .cch-wrapper 节点。全量工具面 18 项中，L3 仅覆盖「注入发生」与「图标存在」，且不校验档位；核心价值「选国→填充」在真实站点上从未被验证过一次。

实证 3

零可观测性、零自检面

src/ 全目录 console. 调用点为 0；无 debug/trace/verbose 开关；无 doctor/self-test 入口。评分证据链 signals[]（detect/index.ts:328,554）算完后只写入私有 WeakMap（:841-842）与 _lowFields（ui/index.ts:260）——算完即不可达。

实证 4

切换语言是手工逐项刷新

_applyLocaleText()（ui/index.ts:750-760）手工重写 6 处文本。漏刷：国家行 .cch-fav 的 title（ui:711）、.cch-empty 文案（ui:699）；图标 title/aria-label 硬编码 'Country Code Helper'（ui:155-156）从未本地化。行业模板要求「字典化后全量重渲染」而非手工逐项补。

架构层诊断（一句话）：本仓库当前的失败模式不是「功能写错了」，而是「写入面」与「读出面」不对等——代码里写入了语言偏好、档位判定、信号证据、注入状态，但读出面（用户可达的设置入口、可读的诊断输出、可断言的能力矩阵）都没有跟着长出来。两个痛点、三个子代理发现、三个未本地化字符串、一套无法驱动的测试 harness，全是这一件事的不同切面。

C1 · 设置入口分层：给设置一个「一级地址」

Strong
Files
src/main.ts:135-137 · src/ui/index.ts:296,312,463-573,750-760
Problem
所有设置（语言/低调样式/豁免/规则）都挤在同一个 #cch-rules-view 里，而该视图的语义标签是「站点规则」；语言控件排在最后、在可滚动容器底部。无独立入口、无 GM 菜单项。这是 Cycle-5「入口自锁」的同类缺陷在设置层的重演：面板已可达，但设置仍需穿过语义不匹配的第二层。
Solution
按行业分层模板（1–3 高频项在首层、4+ 项归专门设置面）：把设置收敛到一个明确的「设置」视图（入口 = 面板头部一个 ⚙ 按钮 + GM 菜单新增一项 t('settings')），语言作为其中一项且排在前部而非末尾；面板首层只留最高频动作（搜索/收藏/填充）。不改评分引擎、不改任何设置语义。
Benefits
locality 好：改动集中在 ui/index.ts 的视图切换与一个菜单注册点；leverage 高：一次性把「所有设置都难找」收敛为「一个入口找所有设置」，直接消解用户投诉。
设置从「规则视图的尾部」提升为「一级设置面」

C2 · i18n 完整性：全量重渲染 + 菜单原地更新 + 补齐未本地化文案

Strong
Files
src/ui/index.ts:155-156,699,711,750-760 · src/i18n.ts · src/main.ts:135-137
Problem
（a）切换语言走 _applyLocaleText() 手工逐项重写，已漏刷收藏 title 与空态文案；图标 title/aria-label 硬编码英文，从未本地化。（b）已注册的 GM 菜单标签只求值一次，运行时切换语言后不更新（需重载）。（c）main.ts:107 的帧校验提示是就地双语三元表达式，未走 i18n 表（注释自认「收口时可收编进 MSG」）——已是遗留债。
Solution

Benefits
locality 好：本地化契约从「N 处手工刷新」收敛为「一处 data-i18n + 一次全量重渲染」；leverage 中高：新增文案不会再漏刷，且消除「切了语言但部分 UI 不变」的信任损耗。
本地化从「N 处手工刷新」收敛为「一处标记 + 一次全量重渲染」

C3 · 自检面：把「为什么没生效」变成一条可追溯的决策链

Strong
Files
src/detect/index.ts:290,328,554,841-842 · src/ui/index.ts:28,260,456-460,736 · src/main.ts:135-137 · src/config.ts
Problem
三种静默失败今天都无解释：（a）无可信字段 → 无图标，理由（gate:input-type/gate:aria-hidden/country-semantic:suppress/gate:visibility-hidden 或分数不足）存在但从不外显；（b）子帧点图标无响应 → _requestRemoteOpen fire-and-forget，无 ack 无超时；（c）选国未填充 → 能报「失败」但不报「为何失败」（FillResult 无 reason 字段）。signals[] 算完即丢进私有容器。这是「无法向用户解释自己」的根因。
Solution
按行业三件套模板：（1）决策链 trace 作单一事实来源——注入/检测/填充各判定点 append {step, verdict, msg, ts}（对标 Flagr evalDebugLog），面板与 CI JSON 从同一份 trace 渲染；（2）面板逐层点亮——每层一个布尔 + 一句已验证根因，第一处熄灭即答案（对标 Greasespot 排障树）；（3）debug 开关门控 + 零开销——trace 只在开启时记录（对标 uBlock logger「未打开则零 CPU/内存」）。入口 = GM 菜单新增「诊断」项 + 设置视图内一节。
Benefits
locality 好：signals[] 已经存在，只是需要一条读出管道，不需重写引擎；leverage 极高：一次性把「脚本没反应」从死胡同变为可回答的问题，且同一个 trace 同时服务用户与 CI——直接兑现用户的第二条诉求。
一份 trace 同时服务「用户看为何」与「CI 可断言」

05行业心智模型模板库（可直接复用的轮子）

本节每一条都来自 atomcode 深度调研（Exa + Tavily + AnySearch 三引擎、官方文档优先、多源交叉）。原则：复用成熟轮子，不重复开发。

设置入口与 i18n（R1，Confidence 高）

S1
设置分层（1–3 首层 / 4+ 专门面）
1–3 个高频快捷开关 → 首层（popup/面板首屏）；4 个以上或需分类 → 完整设置面。混合型 = 首层放最高频 2–3 个 + 一个「设置」入口。反模式：把 15 个设置塞进首层「求简单」——实际是更小更难读。分组按用户意图（General/Appearance/Behavior/Advanced）而非实现细节。
Chrome 官方 Give users options · ExtensionBooster 综述 · Dark Reader 案例
S2
GM_config 模式（油猴事实标准）
声明式设置 schema（text/number/dropdown/bool）→ GM_registerMenuCommand('设置', setup) 打开面板 → GM_setValue/getValue 持久化 → onsave 回调触发界面重渲染。菜单项无图标/无子菜单/无法控制出现位置是已知局限（TM #2461）。
Greasy Fork gm_config_toolbar · Tampermonkey 官方文档
S3
菜单命令 id 原地更新
GM_registerMenuCommand(name, fn, { id }) 支持用同一 id 原地更新已注册的菜单项（含 title/accessKey/autoClose）。正解：语言切换后重注册同一 id 的菜单项，而非等用户重载页面。
Tampermonkey 官方文档（已核验）
S4
i18n 全量重渲染
chrome.i18n 不能做运行时切换（只绑定浏览器 UI 语言）→ 自建内联字典 + t(key)；解析优先级 显式选择 > 浏览器语言 > 默认（与 CSS 级联 / Accept-Language 协商同构）；切换后字典化全量重渲染（[data-i18n]）而非手工逐项改文本。i18next 类库运行时 205–422KB，对单文件 userscript 不可接受。
Chrome i18n 官方文档 · 本仓库 A-019 已对齐解析优先级

指定页面验证与断言阶梯（R2，Confidence 高）

D1
断言阶梯 L0–L5
L0 注入发生 → L1 无副作用 → L2 面板可开 → L3 交互原语生效 → L4 写入生效（字段 value + input/change 事件） → L5 反馈提示。取舍规则：L0–L2 适合真实站点层（低交互高鲁棒）；L3–L5 涉及多步驱动、flaky 乘性增长，应放自有页面层。注意：CDP Autofill 域只观测原生管线，不可用作脚本填充断言（本仓库 cdpNote 已正确登记）。
Playwright 官方 · Chrome 官方 E2E · 本仓库 site-manifest
D2
owned 指定页面 + 交互原语
Playwright 官方铁律「Only test what you control」——第三方页不适合深交互。Contentsquare 的解法：用自有 QA 域做全交互 E2E（externally_connectable + 外接消息唤醒自测），28 个 E2E 自动化 17 个（73.7%）。落到本仓库：把真实站点形态冻结快照为自有指定页，在它上面跑 L0–L5。交互原语模板：inject / open-panel / search-type / select-country / fill-field / feedback-toast，全部用 web-first 断言 + expect.soft 一次收全量。
Playwright 官方 best-practices · Contentsquare 工程博客 · QASkills 2026
D3
flaky 治理：触发面隔离
advisory 的正确实现不是 try/catch，而是把不稳定层从 blocking CI 的拓扑里物理移出（仅 schedule + workflow_dispatch，永不进 pull_request）——这是唯一不会被「配置漂移/误触发」击穿的方案。skip 必须带非空 reason + ticket（Chromium failing_test_names 同构）。断言强度公式：站点可控度 × 断言必要性 × flaky 成本。

零开销 logger + 静默失败三招
uBlock：统一时间线记录「一切发生的事」+ 颜色编码动作类型，且未打开时零 CPU/内存开销——诊断面必须与运行热路径解耦。静默失败三招：前移（构建/保存时校验必需元数据）、捕获（注入探针 + window.onerror 上报 trace）、归因（文案指向已验证的开关；未知错误诚实报「未知 + 请开 debug」）。

06顶层建议与 message 步骤

顶层建议（先做哪一项）：C1 设置一级入口 + C3 自检面。理由：这两项是唯一直接对应你两条投诉的改动，且共享一个交付物——一个「设置/诊断」视图（设置项 + 逐层点亮的自检结果），一处改动同时兑现「能被找到」与「能被解释」。C2 紧随（i18n 完整性，与 C1 同一改动面）。C5→C4 是「能被证明」的地基，因为没有交互原语就搭不起断言阶梯。先让用户找得到，再让用户看得懂，最后让 CI 证得了。
