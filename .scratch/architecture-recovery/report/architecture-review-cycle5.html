00目标（/goal · 不设预算）

本轮目标不是“再修一个引擎 bug”，而是把系统从“在代码正确性上反复加杠杆”切换到“让修复真正送达并被用户看见”。

G1 · 送达

最后一公里

v1.5.0 的安全修复、弱线索识别、三条用户上报 bug 修复全部堵在分发链路上。目标：让任何渠道安装的用户都能收到更新。

判据：Greasyfork 上线版本 = tag = 产物 @version。

G2 · 可见

入口可达

低置信字段页面无图标→无面板→无召唤入口，脚本在用户眼中等于“没注入”。目标：与字段分数无关的全局入口存在且可见。

判据：score<35 的页面仍能打开面板。

G3 · 真实

绿 = 真实成立

“十门全绿”是幸存者名单；真实站点层启用数为 0。目标：CI 绿重新等价于“真实世界成立”，而非“未修的那几扇门被排除出计数”。

判据：10/10 门可执行；真实站点层至少 1 个 live 目标启用。

推进方式：以 message 步骤（§06）为单位推进，每步一个可验收闭环；不设时间/成本预算。
硬边界：本大脑代理不直接修改代码——调查→立票→实施分离；实施走 $to-spec / $to-tickets / $implement，版本控制走 $but 独立分支。

01执行摘要

引擎已经足够聪明，瓶颈不在识别算法，而在送达与可见。四项硬证据：

实证 1

分发布冻死

产物 @updateURL 全部指向 Greasyfork（vite.config.ts:8），而 Greasyfork 线上仍服务 @version 1.3.4。所有从 GF 安装的用户，更新检查永远看到 1.3.4。

实证 2

入口自锁

#cch-summon 只在 open() 内创建（ui/index.ts:317,326）；open() 仅两个调用点，都以“已存在的图标”为前提；图标需置信度 ≥35。→ 低置信页面无任何全局入口。

实证 3

门禁幸存者名单

10 个票级门中 4 个当场崩（09/13/15/18，SyntaxError）；6 个绿门恰好全部已迁移 stripTypeScriptTypes 装载器。3 个红门仍挂 pull_request——下个 PR 迎面拦截。

实证 4

塔尖为空

74 个密封 E2E 确实在真 Chromium 里跑出厂产物，但页面全部来自本地手写 fixture。真实站点层 2 个 live 目标 enabled:false、selector:null——实际启用数 = 0。

辩证校正（重要）：锐评 Round 3 中最戏剧化的一条——“git 历史第三次归零 / tag 非 main 祖先”——实证不成立。当前 origin/main = e2a10d8e，有父提交（e3dda808），163 个提交，单一 root 76cf9896，且 v1.3.4 / v1.4.0 / v1.5.0 三个 tag 全部是 origin/main 的祖先；git ls-remote origin main 与本地一致。该条按“不可复现”处理，不立票。

C1 · 分发最后一公里：从“推”改“拉”

Strong
Files
.github/workflows/release.yml · vite.config.ts:8 · README.md:47 · greasyfork/
Problem
产物 @updateURL/@downloadURL 全部指向 Greasyfork；GF 侧冻结在 1.3.4，而 CI 里没有任何GF 步骤。用户更新检查永远看到 1.3.4——v1.5.0 全部努力送达人数约为零。

分发链路：BEFORE 断在“无 GF 步骤”；AFTER 由 GF 反向拉取补齐

C5 · 帧治理：嵌套帧静默失败

Worth exploring
Files

Problem
isEmbeddedFrame() 只扫顶层 document.querySelectorAll('iframe, frame')——不穿 shadowRoot、不递归孙帧。多层嵌套（codepen embed 再被嵌、动态 iframe、shadow 包裹）下，子帧点击图标的消息在 main.ts:67 被静默 return：无面板、无 toast、无降级提示。

T1
测试塔 / 金字塔
塔基单测（mock GM_*/chrome.*）→ 塔身 fixture E2E（确定性 100%）→ 塔尖真实站点冒烟（宽断言）→ 塔外合成监控（cron）。规则：每层用例递减、成本递增、真实性递增；真实站点用例只升不降——发现塔身未覆盖的形态，先沉淀为 fixture 再修脚本。

T2
注入语义三分法
测“页面上发生了什么”→ addScriptTag（主世界）；测“扩展发布形态”→ MV3 包装 + --load-extension；测“GM_* 权限语义”→ 只能手动 + 单测层 stub GM API。注意：MV3 content script 跑 isolated world，拿不到页面全局，与 TM 沙箱语义不同。

真实站点用例不写死在代码里，收敛为声明式清单（URL + 期望锚点）。单站失效只改清单一行；清单大小本身就是“真实覆盖面”的可度量指标。断言强度 = 注入后 DOM 出现 + 无未捕获异常；内容正确性全部留给 fixture 塔。

注入 UI 可发现性（5 个模板）

U1
Reduce the Gap
入口离任务越近越容易被发现。信息气味理论：用户只扫描与当前目标相关的元素；藏在工具栏弹窗里的功能，对从未点过图标的用户等于不存在。
Plasmo 官方 · NN/g information scent
U2
横幅盲区反转（反直觉）
用户会习得性忽略“位置像广告、视觉处理像广告”的元素——这是扫描阶段自动过滤，不是看过再决定。右下角“漂浮球 + 高饱和 + 阴影卡片”命中全部广告特征。推论：更安静、更原生的注入物反而被阅读率更高；杠杆在位置与相关性，不在视觉重量。
NN/g 1997/2007/2018 眼动研究
U3
渐进式披露（2 层上限）
切分要正确（高频需求在首层）；通往二层的路必须显而易见；超过 2 层用户会迷路。注入 UI 模板：小图标/角标（L0）→ 展开面板（L1）→ 高级设置（L2 封顶）。
NN/g Progressive Disclosure
U4
油猴三层入口模板
userscript 无法加工具栏图标/右键菜单，唯一标准全局入口是 GM_registerMenuCommand（可在检查页面后动态注册）。模板 = 菜单命令（全局入口）+ 页内情境触发 + 快捷键。代价：入口本身藏在脚本管理器里。
Tampermonkey 官方文档 · HN 社区共识
U5
Grammarly 锚定模式
浮动组件锚定在被作用的文本框旁（非页面角落）+ 可拖拽锚点 + 按站记忆位置 + 状态外显（“发现 N 个问题”）+ 最小足迹模式（只留下划线）。解决“浮动球挡住页面功能”的头号抱怨。
Grammarly 官方用户手册

跨帧架构（3 个模板）

F1
全帧自治 + 顶层中心化
每帧独立检测与填充，只有顶层帧承担面板宿主与 UI。1Password / Bitwarden / 本仓库票 12 不约而同收敛于此。第一决策变量：哪个帧拥有这个表单。
Chrome 官方 content scripts · MDN
F2
消息黄金三件套
targetOrigin 尽量收紧 + event.origin 严格相等 + event.source 引用比对 + 信封 schema（type 命名空间 / eventId 去重 / version）。跨域锚定不可得时退化为 source 引用比对。
Chrome 官方模板 · ceaksan · spaceraccoon
F3
