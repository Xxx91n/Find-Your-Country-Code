# 0003 — 引入站点规则引擎，把"完美检测"转为"检测 + 用户兜底"

状态：accepted | 日期：2026-09-04 | 来源：架构恢复 C5（report/architecture-review.md）

## 决策

新增 `rules` 模块 + `store` 站点规则持久化（GM 独立键 `cch_site_rules_v1`，与收藏键 `cch_v33` 解耦，跨标签页同步）：豁免域名（整站跳过检测）、强制选择器（按声明档注入，无需评分）、页面级分档覆盖（用户显式档压过启发式）、负反馈记忆（误报字段一键记为 none 档）。规则匹配发生在评分之前。

## 被否决路线与理由

- **继续追求零误报的自动检测**："适配所有网站"不可达是结构性的——密码管理器行业也不做 100% 自动，全部保留手动兜底后门（KeePassXC sites.js / Bitwarden linked field / 1Password data-1p-ignore 三源收敛，cited）。
- **远程规则订阅/云黑名单**：油猴脚本无服务端，且站点规则本质是个人化误报记忆，共享价值低、隐私面大。
- **"仅重映射已注入档"的分档覆盖语义**：TDD 断言驱动下选定"页面档位下限"语义——auto/lowkey 覆盖把引擎 none 档也提升注入，与 1Password 显式干预哲学一致（票 05 偏离点）。

## 后果

误报有了体验出口：用户拥有最终控制权，而非被启发式绑架。选择器有效性当前不在写入时校验（非法选择器静默不命中），UI 层（票 07）写入前应做 querySelector 预检（票 05 报告风险提示）。
